# Spec questions and verification limits

| Spec and criterion or section | Question or limit |
| --- | --- |
| `api-conventions.md` — Q-API-3, Open questions | How can QA reliably induce an internal HTTP 500 through the public API? Backend exception-envelope verification requires a public trigger. The browser suite injects a synthetic 500 to exercise UI handling. |
| `api-conventions.md` — API-AC3, and `settings.md` — SET-AC8 | Should API-AC3 apply only to validation errors with code `invalid_request`? API-AC3 says every 422 has that code and validation details, while SET-AC8 explicitly requires a 422 `model_not_supported`. The suite verifies the documented validation envelope and the settings-specific result. |
| `api-conventions.md` — Edge cases and failure modes, non-API paths | The section makes behavior depend on whether the UI is built but leaves missing non-API paths unspecified. What should an arbitrary non-API path return in each build state? The HTTP suite checks the documented `/api` error shape and the browser suite visits the built root. |
| `chat.md` — CHAT-AC13, Edge cases and failure modes, Q-CHAT-4 | Can a scripted black-box provider induce `malformed_model_output`, `agent_loop_limit`, `model_unavailable`, or a request failure after using tools? The documented setups cannot exercise the 502 cases, the selected-model 503, or failed usage accounting after a completed tool call. CHAT-AC13 covers the documented invalid-key 503. |
| `chat.md` — Edge cases and failure modes, Q-CHAT-3 | Is the 20-message context window a requirement, and can QA observe it deterministically through a public test provider? The demo provider does not make prior context observable. |
| `sessions.md` — Edge cases and failure modes, Q-SESS-2 | Is there a specified count and elapsed interval QA should use to verify no practical cap or automatic expiry? The suite checks 51 conversations and retention across restart. A finite run cannot prove the absence of a cap or time-based expiry. |
| `tools.md` — Edge cases and failure modes, Q-TOOL-1 | Can QA supply custom tool calls through a documented public test provider? Direct checks of unknown, differently cased, padded or blank project arguments, extra arguments, denied or write/delete/send requests, and both tool-call caps are deferred as directed by the spec. Prompt normalization, omitted project arguments and a one-character-only note query are covered. |
| `web-ui.md` — Edge cases and failure modes, dark mode | What minimum contrast or visual acceptance reference defines readable contrast in dark mode? The suite checks that the browser preference changes theme colors and leaves the composer visible. |
